## Bugs found and fixed (reproductions use a claude.ai stand-in, script in the session scratchpad)

1. **"Saved" shown and the safety copy deleted while newer edits were unsaved.** Type, wait until the save starts (about 0.7 s), type again before it lands: the first save finishing cleared `dirty` and the browser draft and showed "Saved 13:00", though the database still held the older text. If the second save then failed, the edits were gone. Now a save that lands behind newer edits goes to `pending` (event `behind`), keeps the draft, and the next save follows.
2. **Retry could start a second write in parallel.** After the first `unavailable` error, the retry cleared the "in flight" marker before the retry finished, so another edit could start a concurrent write. The retry is now inside the same in-flight promise (`retrying` state), and `flush()` resolves only after queued saves are written. So "Archive" waits for its own write.
3. **Page stuck on "Loading assessments…" when a capability is refused.** If `window.claude.use(...)` rejects, `init` threw and the page stayed in `starting` with no banner. Now a refused capability counts as missing, and the page shows "Saving is not available here." Repro: `window.claude = { use: () => Promise.reject({ code: 'capability_disabled' }) }`.
4. **Dead editor after a failed permanent delete.** As owner, archive an interview, press "Delete permanently" while the database refuses: the editor stayed on screen but every edit was silently dropped (`ED` was cleared). Now a toast says the delete did not finish and the interview is shown again, editable.
5. **Corrupt or foreign draft restored into the editor.** A draft without `info`/`scores`, or for another id, was offered and restored as is. `parseDraft` now rejects it (returns null, never throws), and restored drafts pass `normalizeA`.

Unchanged: locally (no claude.ai) the page shows "Saving is not available here." and keeps nothing; the browser test checks this on desktop and phone.

## AX handles

- `<main id="view">` attributes: `data-view` (`overview | framework | new | assessment | company`), `data-mode` (`starting | nostore | live`), `data-access` (`edit | read`), `data-save` while an interview is open (`saved | pending | saving | retrying | blocked | error`).
- `window.AIAssessment.state()` → `{ view, id, slug, mode, readOnly, isOwner, loaded: {assessments, frameworks}, slow, problems: [...], count, framework, editingFramework, editor: { id, save, dirty, persisted, framework } | null }`.
- `window.AIAssessment.flush()` → promise, settles when the open interview is written.
- Navigation events are the hash routes above (`location.hash = '#a-<id>'`). Stable control ids: `#btnNew`, `#nav-overview`, `#nav-framework`, `#i-company` and the other `#i-*` fields, `#save-state`, `#t-text`, `#t-anon`.

## Tests

- `node tools/assessment/tests/flows.test.mjs`: 12 checks: every transition, rejected impossible ones (`wrote` without a save, a second write while one is in flight, a second retry), no dead ends, the draft round trip, migration of old drafts, malformed drafts.
- Browser (Playwright, with a stand-in for `window.claude`): new interview → pending → saving → saved; one failure → retrying → saved; two failures → error, draft v1 kept, next edit recovers; edits during a save; an old-format draft offered and restored after reload; a corrupt draft ignored; a failed delete leaves a working editor; a viewer gets the read-only banner; refused capabilities give "Saving is not available". No console errors.
- The older suites the README lists (`tests/engine.test.js`, `ui_test.py`, `save_state_test.py`) are not in this repo copy, so they could not be re-run. The scoring engine and the PDF (`engine.js`, `report.js`) are unchanged.
