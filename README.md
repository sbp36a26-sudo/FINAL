# Report Studio

A local tool for EHL Student Business Project Group 36 (client HFTP). You paste raw content in, and it produces finished report spreads that follow the brand guidelines in `brand/brand.json` exactly. If content does not fit, the build reports it. The design never bends.

- **Output:** `out/report.pdf` (one vector PDF, fonts embedded, one page per 1588 × 1123 px spread), `out/png/*.png` (each spread at 2x) and `out/gallery.html`.
- **Requires:** Node.js 20 or later. Chromium comes with Playwright.

```bash
npm install
```

```bash
npx playwright install chromium
```

## Commands

| Command | What it does |
|---|---|
| `npm run build` | Validates and renders every spread in `content/report.yaml` to `out/report.pdf` and `out/png/`. Exits non-zero with one message per problem. |
| `npm run page -- content/pages/<file>.yaml` | Validates and renders one spread to `out/png/<file>.png` and opens it. Set `NO_OPEN=1` to skip opening it. |
| `npm run gallery` | Writes `out/gallery.html` with every layout and component filled with the sample content, plus `out/gallery/<id>.png`. |
| `npm run test:visual` | Visual regression: screenshots the gallery and compares it with `tests/__screenshots__/`. Also proves the render checks catch each kind of violation. |
| `npm run test:visual:update` | Accepts the current gallery as the new baseline, after an intended design change. |
| `npm run lint` | Fails on any raw colour, px value, font size or off-grid spacing outside `brand/tokens.css`. |
| `npm run measure` | Re-derives every layout's limits by rendering, and writes `layouts/<id>.schema.json`. Run it after any layout change. |
| `npm run tokens` | Regenerates `brand/tokens.css` from `brand/brand.json` and `brand/decisions.json`. Build, page, gallery and lint run it for you. |

In Claude Code, `/newpage <paste raw text>` picks a layout, writes the YAML within the limits, asks for any missing source or base, builds, shows the PNG and lists what it cut. The command lives in `.claude/commands/newpage.md`.

## How it fits together

```
brand/brand.json        the guidelines, verbatim (law)
brand/decisions.json    team rulings on conflicts inside brand.json (see below)
brand/tokens.css        GENERATED: the only file with raw colours, sizes and spacing
src/components/*.ts     13 components; each file holds its CSS (tokens only) and its HTML
src/layouts/*.ts        one template per layout, with its JSON Schema, sample content and furniture
layouts/*.schema.json   GENERATED by "npm run measure": schemas with the measured hard limits
src/runtime/runtime.js  in-page: flows text through column boxes, puts footnotes at the page foot
src/runtime/checks.js   in-page render checks (overflow, type size, colours, contrast, grid)
src/validate/content.ts schema limits, number-needs-source, no Wikipedia, image ratios
content/report.yaml     the spreads in order, grouped by section
content/pages/*.yaml    one file per spread
content/images/         photos (placeholders included; replace them)
```

## Content format

One YAML file per spread in `content/pages/`. `section` must be one of the five sections in brand.json, written exactly (for example `"2 Key findings"`).

```yaml
layout: lead2col
section: "2 Key findings"
title: Using AI is not the same as getting value
lead: 91% of hotel chains use AI, but only 28% have a senior-led, company-wide AI strategy and 13% report a measurable return.
figures:
  - {value: 91, unit: "%", label: of hotel chains use AI, source: "h2c (2026)", base: "122 responses from 113 chains; vendor-sponsored, unweighted"}
body:
  - {kicker: Strategy, heading: Strategy lags behind use, text: "Only 28% have a senior-led, company-wide AI strategy."}
chart:
  title: Top barriers named by independent hotels
  unit: "%"
  rows: [{label: Lack of knowledge, value: 39}, {label: Set-up cost, value: 35}, {label: Integration, value: 34}]
  source: Schegg (2025), HES-SO
  base: ~1,485 hotels in AT, FR, DE, GR, IT, CH; 82% independent
```

`content/report.yaml` lists the spreads. `contents: true` adds the generated contents spread at the front.

```yaml
title: "AI in European Hospitality: The Playbook for Hospitality Stakeholders"
contents: true
sections:
  - section: "2 Key findings"
    spreads: [2-0-divider.yaml, 2-1-using-ai-is-not-value.yaml]
```

Spread numbers (2.1, 2.2 …), subheading numbers (2.1.1 …), page numbers, the contents spread and each divider's chapter contents are all generated from the manifest order. Page numbers count A4 pages: spread *n* holds pages 2*n*−1 and 2*n*.

### Layouts and their limits

The limits below are hard: the build fails above them. They were measured by rendering each layout with long dummy text (`npm run measure`). The text fields are measured first, with the other fields at sample length. Body text, item counts and chart rows are then measured with every text field at its maximum. The render check is the final word: a combination that still overflows fails the build with the field named.

| Layout | Fields and limits |
|---|---|
| `lead2col`: Lead + two columns + figures | title ≤ 52 · lead ≤ 229 · body ≤ 8 blocks, ≤ 1,644 characters in total (kicker ≤ 27, heading ≤ 61) · figures 1–4 (label ≤ 84) · chart: title ≤ 119, 2–5 rows (label ≤ 84) |
| `cards`: Card grid | title ≤ 52 · lead ≤ 229 · exactly 6 cards: kicker ≤ 31, title ≤ 61, text ≤ 171, optional figure (label ≤ 74) |
| `zquote`: Pull-quote spread | title ≤ 52 · lead ≤ 229 · quote ≤ 79 · attribution ≤ 250 · body ≤ 10 blocks, ≤ 2,296 in total |
| `halfbleed`: Half-spread photo | title ≤ 52 · lead ≤ 229 · body ≤ 8 blocks, ≤ 1,432 in total · image 1:1.414 (A4 portrait), caption ≤ 157 · `photo_page: left \| right` |
| `strip`: Strip of three | title ≤ 52 · lead ≤ 229 · body ≤ 10 blocks, ≤ 1,856 in total · exactly 3 photos, 1:1, caption ≤ 105 |
| `quote`: Photo + quote band | quote ≤ 79 (no numbers: the band has no room for a note) · attribution ≤ 250 · image 2:1, caption ≤ 43 |
| `inset`: Inset in column | title ≤ 52 · lead ≤ 229 · body ≤ 19 blocks, ≤ 3,864 in total · image 4:3, caption ≤ 105 |
| `divider`: Section divider | image 1:1.414, caption ≤ 157. The number, title and chapter contents are generated. |

Limits are in characters. The exact current values live in `layouts/<id>.schema.json`.

### Sources

- Every number in a text field (digits, %, €, x) needs a `source` and a `base`. They can sit on the same figure, on the enclosing block (a body item, card or chart), or next to the field: `lead_source` + `lead_base`, `title_source` + `title_base` or `quote_source` + `quote_base`. A number that matches a figure or chart value on the same spread cites that figure's source.
- In running text, numbers get superscript references, and the notes appear at the foot of every page that cites them. Key-figure tiles carry their source and base small in the lower part of the tile.
- Any source containing "wikipedia" fails the build.

## What the build checks

1. **Schema:** every field against the layout's measured limits, plus required fields, unknown fields and image ratios (±3 %).
2. **Sources:** the number rule and the Wikipedia rule above.
3. **Render (Playwright, Chromium):**
   - any element whose content overflows its box, or runs into the margins
   - any text below the caption size, or at a size outside the type scale
   - any colour (text, background, border, SVG fill or stroke) that is not a token
   - any text/background pair under 4.5:1, measured against what is actually painted behind the text
   - any block in the type area that starts or ends off the 4 px grid

## Team rulings (`brand/decisions.json`)

brand.json is kept verbatim. Where it contradicts itself, the team ruled as follows:

- **Notes override the component specs.** Titles get an accent rule. Subheadings are a vertical bar plus a numbered capital label. Figure sources sit inside the tile. Page furniture has both the top tab and a vertical section strip on the outer edge, which links to each section in the PDF.
- **Block gap:** 32 px. brand.json says 30, which is off the 4 px grid.
- **Body line height:** 24 px (15 × 1.62 = 24.3 snapped). Other line heights are snapped to 4 px multiples in the same way.
- **Page grid:** measured from the spine. Inner margins are 96 px; outer margins are 98 px, because a 794 px page is not a multiple of 4. The content area is 600 × 928 px, in two 284 px columns.
- **Contrast:** section colour is darkened in 10 % steps whenever it carries text, not only under white text. Results: Final words #966C23 (2 steps), and darker tile variants for Key findings, Opportunities and Final words. On the 10 % tiles, muted grey fails AA, so tile sources use ink.
- **PDF:** one page per spread.
- **Contents:** a generated contents spread at the front, plus chapter contents in each divider.

## Fonts

Archivo 700 and Source Serif 4 (400 and 700) are installed with `@fontsource` and self-hosted in `out/assets/fonts/`. Rendering never touches the network, and the PDF embeds both families as subsets.

## Hand-off to Canva

1. Run `npm run build`.
2. In Canva, choose **Create a design → Import file** (or drag the file onto the home page) and upload `out/report.pdf`. Canva converts the PDF so text boxes, shapes and images become editable elements. Each spread arrives as one 1588 × 1123 px page.
3. **Fonts must match.** Canva can only keep text in Archivo and Source Serif 4 if those fonts are available to the team; otherwise it substitutes another font and line breaks change. Before anyone edits:
   - Add **Archivo** (Bold) and **Source Serif 4** (Regular and Bold) to the team's Brand Kit (Brand Kit → Fonts → Upload a font). Upload the static .ttf files from Google Fonts. Uploading needs a plan that allows custom fonts.
   - The fontsource build of Archivo 700 names itself "Archivo SemiBold" internally, although its weight is 700. If Canva shows "Archivo SemiBold" after import, select those text boxes and set them to Archivo Bold.
4. Treat Canva as the place for last-minute wording fixes only. Size, colour, spacing and layout changes belong in Report Studio, where the checks run. Otherwise the PDF and the guidelines drift apart.

## Visual regression

`tests/__screenshots__/` holds the baseline screenshots of every gallery spread, rendered on Linux Chromium. Font rasterisation differs slightly between operating systems. If you run the tests on macOS or Windows, create a local baseline first with `npm run test:visual:update`, then compare after each change.
